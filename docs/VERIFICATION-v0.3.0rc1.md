# Verification for KMDStudio 0.3.0rc1

27 November 2026, Europe/Moscow. The candidate passes the editable DOCX, illustration, and portable-package checks. Qualified PDF delivery and comparative agent evaluation remain open. This is a development candidate. The [0.2.0 record](VERIFICATION.md) and [0.1.0 record](VERIFICATION-v0.1.0.md) retain the historical evidence.

## Baseline and acceptance

The project version at intake was 0.2.0. The local verification index had no commit history, and the authorized public GitHub repository advertised no refs. The first published commit captured the reviewed 0.2.0 workspace. Its three packaged benchmarks regenerated byte for byte with site packages disabled on Windows CPython 3.15.2. The baseline passed 25 of 25 tests in the project environment, with three optional PDF tests skipped in the system environment. [Baseline commit](https://github.com/apollogens/KMDStudio/commit/899e36069049ca6e43f1b59b975914ba8ce4ed9a)

The new [fixtures](../examples/benchmarks/visual-intelligence) fix all text and required block IDs. The gallery must include the approved original image, caption, alternative text, and exercise prompts. The algorithms guide must preserve all 40 lines of its listing, including a 92-character line. The dispatch report must preserve 32 native rows, their header cells, and totals of 1,725 planned and 1,699 actual. The five review statuses must remain searchable.

The gallery and dispatch fixture hashes were `c7fa8b67c222a4d85f90227ced21632853efb2cf427b0b49002146057750443c` and `5f8e467a4d58862769927f78a65f700d810082be235aa35acd512fabbd961396`. ## Reproduce the checks

```powershell
python -E -s -B -m unittest discover -s tests -v
python -I -B -m pip --isolated install --index-url https://pypi.org/simple --require-hashes --only-binary=:all: -r requirements/ci.lock
python -E -s -B -m unittest discover -s tests -v
ruff check skills tests tools evals
python -m pip check
python -E -s -B tools/audit_dependencies.py
python -E -s -B tools/verify_bundle.py --archive artifacts/v0.3.0rc1/kmdstudio-0.3.0rc1.zip
```

Use a separate virtual environment for the optional packages. Windows CPython 3.15.2 passed 25 tests with five skips in the standard-library environment and 30 of 30 in the project environment. The official skill-creator validator also passed. OSV returned no advisories for the checked Pillow, pypdf, and Ruff versions on the verification date. [OSV query reference](https://google.github.io/osv.dev/post-v1-querybatch/)

For independent Open XML validation, open each read-only DOCX as a `WordprocessingDocument` and call `OpenXmlValidator.Validate` using Microsoft Open XML SDK 2.9.1. Local Word automation opened each synthetic document read-only with macro execution disabled, called `Repaginate`, and queried page, table and inline shape counts, plus the gallery alternative text. [Microsoft SDK validation guidance](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-validate-a-word-processing-document)

## Agent evaluation

**PARTIAL** for infrastructure. The earlier 150-second comparison produced shell command events and access-denied failures without completed turns. The new run used a fresh workspace outside the repository, explicit `gpt-5.6-sol` and low reasoning, and a 45-second local-file smoke. The provider emitted `turn.completed` in 37.78 seconds. The trace contained zero terminal commands and one MCP resource-listing attempt. The agent reported that it could not read the fixture and never returned its contents. This confirms model connectivity and leaves local tool execution unverified for the nested host.

**NOT RUN** for the three-arm report. The smoke gate stopped the pilot. Actual smoke usage was 313,651 input tokens, including 282,624 cached, and 1,051 output tokens, including 432 reasoning output tokens. No activation, content, quality, corrections, or comparative efficiency scores are available. Raw traces and workspaces remain local. The [standalone evaluation procedure](../evals/README.md) uses a bounded smoke followed by one controlled comparison.

## Qualified PDF delivery

**BLOCKED** on the tested Windows host. Structure tests run with the pinned parser. The earlier renderer qualification could not demonstrate network denial for the renderer and its descendants. The current iteration did not repeat that environment or change host controls.

An operator can qualify another environment with an approved sandbox and a patched, trusted LibreOffice build. First test a synthetic process and its child against a permitted workspace and denied paths and network endpoints under the same policy. Record the effective filesystem boundary, network denial, resource limits and descendant cleanup. Run the [documented export command](../README.md#optional-pdf) only after those checks pass. Confirm the validator accepts the new static PDF, check every page visually, and record application and font versions. Test PDF/UA and screen-reader interaction separately before making accessibility claims.
