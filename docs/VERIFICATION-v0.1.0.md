## Security validation

- Tests exercised Windows case handling, NTFS junctions and hard links, unsafe paths, bounded JSON and XML, malformed ZIP entries, duplicate parts, asset hashes and notices, unexpected document fields and relationships, and prohibited PDF structures.
- The DOCX CLI verified the exact editable body text and block order of both delivered examples. PDF export regenerated and verified its DOCX input before starting LibreOffice with a disposable profile and restricted process environment. The optional parser checked the rendered PDF structure before publication.
- OSV returned no matching advisories for `pypdf 7.2.0`, `PyYAML 6.0.4`, and `ruff 0.17.6` when queried on the verification date. The request contained only these three package names and versions. This advisory check says nothing about unknown vulnerabilities or the OS and native toolchains. [OSV batch query API](https://google.github.io/osv.dev/post-v1-querybatch/)
- LibreOffice came from the Windows MSI published by The Document Foundation. The published SHA-256 matched and Windows reported a valid Authenticode signature for the foundation. Administrative extraction was isolated to the project. [Publisher's mirror and checksum](https://download.documentfoundation.org/libreoffice/stable/26.8.3/win/x86_64/LibreOffice_26.8.3_Win_x86-64.msi.mirrorlist)
- See the [threat model](threatmodel.md) for filesystem races, limits of the allowed-document profile, operator authority, and host sandbox duties.

## Rendering and visual assessment

LibreOffice Writer 26.8.3.1 converted the generated DOCX files. The existing Ghostscript 10.03.1 rasterized only these checked synthetic PDFs at 125 dpi with `SAFER` active. The bundled generic DOCX render helper could not start because its `pdf2image` dependency was absent. The project-specific LibreOffice path and local rasterizer completed the review.

| File | Assessments |
| --- | --- |
| `python-oop-lecture` | Five A4 pages. The page sequence is cover, class and instance diagram, editable and highlighted listing, interface table, and practice. Observed Cyrillic glyphs, line wraps, footers 1–5, and the outline and reading sequence at page scale. The tagged PDF catalog declares `ru-RU`. |
| `workshop-status` | One A4 page. Observed the header, three-column table, separation from the following paragraph, decision callout, and footer. The tagged PDF catalog declares `en-US`. |

Visual inspection used the rendered pages of both outputs. Word for Windows, screen-reader behavior, PDF/UA conformance, and font substitution on other hosts remain unverified. The installed Arial, Georgia and Consolas faces used by the examples reported OpenType `fsType=8` for editable embedding. The repository does not redistribute the font files. [OpenType embedding flags](https://learn.microsoft.com/en-us/typography/opentype/spec/os2#fstype)
