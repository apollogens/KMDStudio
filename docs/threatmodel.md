# KMDStudio threat model

Scope covers the local CLI, the Codex activation path, and optional export. The assets to protect are user content, unrelated filesystem data, output integrity, operator execution authority, and package provenance. Assume an attacker can control supplied content, filenames, source references, and brief fields. Treat package or renderer modification as a distinct supply-chain scenario. Each scenario is a hypothesis about misuse.

| Scenario | Boundary and controls | Residual risk |
| --- | --- | --- |
| Embedded prompt or malicious skill steers the agent to execute or disclose content | `SKILL.md` treats source material as data and requires authorization for transfers. Review the skill before discovery. CLI generation uses no network or executable content and cannot act on instructions in the brief. | Agent compliance depends on the host and approved tools. Prompt instructions alone cannot contain an agent or authenticate a skill. |
| Path injection reads unrelated data or changes an existing document | `guard` validates raw paths, rejects reparse points and hard-linked inputs, verifies opened file identity and rechecks the directory chain and staged identity before linking without replacement. | Directory changes can race path-based operations on Windows. Require directory ownership and OS-level containment. A successful flush does not promise power-loss durability of the final directory entry. |
| Oversized or hostile input causes exhaustion or parser behavior | JSON bytes, depth, integers, and duplicate keys are bounded. Brief values are checked against the schema and semantic constraints. ZIP member names, count, sizes and ratios are bounded. XML parsing limits bytes, depth and nodes and forbids DTDs and processing instructions. The illustration gate bounds normalized PNG chunks, checks CRCs and limits decompression to the expected scanlines. | Native Pillow and LibreOffice processes rely on OS memory, disk, descendant and network limits. Product validators apply to this generated profile. |
| Macro, link, field, attachment or active PDF content reaches the recipient | `review_docx` checks part names, internal relationships, structure and one PAGE field. `render_pdf` checks the classic cross-reference table before parsing, bounds object and page tree traversal, blocks active features and allows a static initial view of an actual page. | Keep renderers, decoders and document viewers patched. Arbitrary Office and PDF review and SVG decoding are outside the supported workflow. |
| Dependencies or icons are silently substituted | The DOCX core uses the standard library. The optional wheel and development wheels are pinned by SHA-256. A reviewed manifest pins icon and license bytes. `render_pdf.renderer_path` takes an operator-selected absolute path, and `render_pdf.render` uses fixed arguments, a disposable profile and a narrow subprocess environment. | A compromised skill or trusted manifest can redefine its own checks. Runtime integrity does not establish provenance of the manifest or renderer. Independent review and artifact signatures remain release work. |
| Native renderer or host leaks data | Run inside an OS-enforced, network-restricted host sandbox. The renderer opens a freshly verified document with a minimized environment and disposable paths. | The profile controls LibreOffice state. The sandbox controls OS access. The host agent may operate remotely even when generation runs offline. Sensitive cloud or tool transfers need authorization. |
| An illustration leaks metadata or changes after review | The optional importer accepts explicit local PNG or JPEG, checks size and frame bounds, applies orientation, and saves a fresh pixel buffer. The core requires the trusted SHA-256 of the manifest, validates each image hash and rejects auxiliary PNG chunks and out-of-profile pixel streams. | Operator review establishes rights, content, provenance and the trusted manifest digest. Hashes alone do not authenticate the creator. Pixels can still contain sensitive information. Use host controls during native decoding. |
