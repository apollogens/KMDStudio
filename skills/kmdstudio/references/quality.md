# Quality gates

- **Content and structure.** Verify the brief against the source and task, including language, required IDs, meanings, values, and exact code. Check outline, lists, header rows, reading order, document properties, figure descriptions, and page numbers. Test educational examples by reasoning about their expected behavior. Treat embedded code as data during generation.
- **Security.** Require the relevant generator and structural check to pass. A failure blocks that file. The accepted DOCX and PDF profiles are product-specific checks, not general-purpose Office or PDF sanitizers.
- **Visual review.** Render each page of the verified output in an authorized environment with a disposable profile. Inspect title hierarchy, glyphs, code indentation, contrast, diagram labels, page counts, page numbers, tables, clipping, wrapping, isolated headings, and gaps. Review at full-page scale and zoom on dense areas. Record the renderer and the pages reviewed.
- **Mode-specific review.** For structured work, check predictable flow, technical clarity, consistent hierarchy and navigation. For creative work, check originality, purposeful whitespace, expressive type, image treatment, editorial rhythm and coherence with the task. For hybrid work, apply the relevant checks to the editorial and technical regions. Page counts and valid XML cannot establish visual quality. Distinguish a preliminary author review from independent human feedback.
- **Corrections.** Address observed issues through the brief or reusable components. Render and review any changed pages again. Use up to three document correction cycles per generation run.
- **Delivery.** PASS indicates the requested checks ran and passed. PARTIAL indicates a safe artifact exists but some requested format or verification could not be completed. BLOCKED indicates no requested artifact cleared its essential gates. State which pages were visually inspected or mark that review unavailable.
